# 加密助手 · Android 端

> 当前阶段：Android 主功能已实现，当前源码版本 **`1.4.0` / versionCode 26**（applicationId `com.cryptoassistant.app`）；许可证 **GPL-3.0-only**。项目按**开源、侧载分发**推进，**不计划上架 Google Play 或国内应用商店**。
> 功能包括源码审计、首页「使用说明」工具书（8 章 33 节）、**简体中文 / English 双语界面（跟随系统或 Android 13+ 应用语言）**、悬浮球标准/便捷模式、文件/目录流式加解密、VOLU 单卷读取与外部分卷写入、合卷后安全解压、VIEW/SEND 单入口判型、完整密钥备份、可选生物识别安全锁（密钥与日志敏感操作前验证）与可选应用锁（只锁主界面，默认关），分级诊断日志、缓存清理与租约、T9 胶囊展开、T12 便捷模式磁贴、T13 每次点球的无障碍引导面板、**D20 输入框结构日志/写后回读探针**，以及 **T14 阶段 1–3 的点球整框读取、写前重读与 150/800ms 回读验证**。真机矩阵仍有未完成项，见下方交接状态与局限。
> **文字加解密只发生在悬浮球**：应用内不提供独立的文字加解密页。
> 文件加解密在「文件」页完成：SAF 可一次选多个文件，或选一个文件夹递归收集，按顺序流式处理；
> 解密也支持当前外部分卷（VOLU）；结果留在应用私有目录，再逐个分享、另存或用其他应用打开。
> 设置页可查看并手动清除临时结果；分享/打开租约在启动成功后才写；保存成功会标记“已保存”，
> 但临时结果仍按离开页面/6 小时租约规则清理。密钥页的创建时间来自完整备份，旧 GCM1 显示“未知”。
> 本应用对外注册**一个**文件入口「加密助手」
> （`ACTION_VIEW` / `ACTION_SEND` / `ACTION_SEND_MULTIPLE`，`content://` 与 `*/*` 都收）；是否出现在真实微信、QQ、文件管理器的候选列表尚未完成真机矩阵验证。
> 被调起后按文件名/文件头判型，`.aegix` 进解密页，其余进加密页；
> 单文件不再弹二选一；多文件混合时让用户选“只解密密文 / 只加密普通文件 / 取消”。

- 悬浮球文字加解密（**工作模式开关**：打开 = 便捷模式，关闭 = 标准模式；实时生效，用户选的模式优先于系统权限状态）：
  - **便捷模式（需要无障碍）**：单击球就地变形——无障碍服务先读焦点输入框（有选区取选区）并自动判断内容，
    明文就加密、密文就解密，结果写回**同一个输入框**；长按球打开菜单只用来改收件人，
    文件页从首页或系统单一入口进入；
    主界面不会被拉到前台（`taskAffinity=""` + 独立任务栈）；
  - **标准模式（完全不碰无障碍）**：单击球打开一个文字输入面板，**不自动读剪贴板**；
    面板只有一个输入框：空输入时标题为「文字加密解密」并显示盾牌图标，提示语为
    「在里面粘贴明文或者密文进行加密或解密」；有内容后才判断方向——普通文字标题变「加密文字」
    → 加密并复制到剪贴板；本工具密文标题变「解密文字」→ 解密；
    「从剪贴板填入」是用户主动点击才会读剪贴板的按钮。接收方只在长按菜单里选择；
    **多联系人且未选择时阻止加密**；只有一个联系人时自动选中并显示；
    长按菜单不再承载动作行，文件入口回应用首页，剪贴板解密由剪贴板磁贴或点球兜底；
    全程不出现「无障碍 / 降级 / 替换输入框」字样；
  - 标准模式关闭后台剪贴板监听：复制密文不会自己弹明文胶囊；只有点剪贴板磁贴，
    或点球后走剪贴板兜底时才读；
  - 剪贴板读取统一走「临时取得焦点 → 读 → 立即恢复」，**不再被无障碍开关挡住**：
    便捷模式读不到输入框时的兜底、剪贴板磁贴、以及点球后的剪贴板路径都走这条；
  - 工作模式属于低频设置，只在「设置 → 悬浮球与无障碍」里切换；切换会立即关掉开着的菜单/胶囊，
    标准模式从此不再读输入框；
  - 写回时序：便捷模式不需要胶囊——点球时读取焦点控件快照，加密/解密完成后直接写回同一个控件；
    只有解密结果会用拉长的胶囊展示明文。旧版“胶囊关闭后再写回”的路径已被 T15 删除（2026-10-30）；
  - 加密：本机私钥签名 + 联系人公钥混合加密，输出桌面端同款 Base64 并原地替换输入框内容；
    只在写不进去时才降级为「复制密文到剪贴板」并提示原因；写后按 150ms→800ms 回读确认，只有确认已变才记 `writeback=true`（T14 阶段 3）；微信聊天框读不到属 H6-H，改走 W1/W3 剪贴板兜底（见 §6 第 3 条）；
  - 解密：只有识别为本工具密文才解密；便捷模式会尝试把明文直接写回同一输入框，并把球拉长为胶囊展示明文，
    不会自动进剪贴板（写回失败也不自动复制）；胶囊关闭/超时即清除（普通 20 秒，展开最长 120 秒）；
  - 输入框里不是本工具密文时按普通文字加密，不会做破坏性解密；密码框/PIN 直接跳过；
  - 便捷模式无障碍服务没连上时（含“系统里已启用但服务没运行”）：**每次**点球都打开专用引导面板（T13，2026-10-29）。
    面板按「未开启」/「服务没运行」分支标题与主按钮（去开启 / 去修复），内含便捷模式开关和「先按剪贴板处理」出口；
    面板打开时**不预读剪贴板**，只有用户点剪贴板出口才读；面板打不开时 Toast 并走剪贴板兜底；
  - 无障碍已连接但当前没有可用输入框时，直接按剪贴板兜底，不弹无障碍引导：密文解密；明文且已有接收方时加密后放回剪贴板，提示「已加密给 X · 长按粘贴」；明文但没有接收方时只提示先长按球选联系人（W1/W3，2026-11-02）；
  - 双向保险：剪贴板是密文时拒绝重复加密，是普通文本时拒绝破坏性解密，两者都可一键切换动作；
  - 签名逐一遍历联系人公钥验签，标明「签名有效 · 来自 X」或「发送者未识别」；
  - 记住上次加密的联系人（下次点球默认选中并标「上次加密」，被删除则自动回退）；
  - 加密结果页写明「加密给 X · 指纹尾号」，防止发错人；
  - 明文面板显示「停留 N 秒」逐秒倒计时，归零自动关闭；复制后提示「已复制，可以粘贴发送了」；
  - 剪贴板读取被系统拒绝时给「重试」入口，不再只能关掉重来。
- 密钥管理（真实可用，非占位）：
  - 生成 4096 位 RSA 密钥（桌面端兼容下限；2048 位受既有校验限制无法生成）；
  - 私钥由 Android Keystore 中的 AES-256-GCM 密钥包装后落盘，日常加解密无需口令；
  - **完整密钥备份（只用文件）**：一次导出包含公钥、指纹、密钥长度与口令加密后的私钥（内层仍是 GCM1），
    导出后直接通过系统文件选择器保存为 `.txt`，不再显示可复制的备份文本；导入时用系统文件选择器
    选择该 `.txt`（自动预填名称、提示完整备份还是旧版 GCM1），不再提供粘贴文本框；
    新备份与旧版纯 GCM1 都从私钥重新推导公钥/指纹，公钥与私钥不一致时拒绝；
    备份内容不经过剪贴板；公钥可在密钥页点按身份卡直接复制；
  - 联系人保存对方公钥与指纹，支持从剪贴板粘贴、复制公钥、删除确认；拒绝把自己的公钥
    加为联系人，拒绝重复公钥。
- **可选生物识别安全锁（BIO-1–BIO-3，2026-10-31）**：设置 →「安全锁」，默认关闭；
  开启后导出备份、导入替换、删除本机密钥，以及导出/清空日志、更改日志等级前都要过系统 `BiometricPrompt`，取消/失败不执行；
  开启与关闭安全锁本身也要验证，没有“跳过验证”的隐藏入口。Android 9+ 允许锁屏凭据兜底，
  Android 8.0/8.1 只接受生物识别；无可用验证方式时禁止开启并给出恢复路径。
  不改私钥的 Keystore 包装、备份口令或密码学线格式；创建密钥、复制公钥、联系人、日常文字/文件
  加解密不验证。**应用锁（BIO-4，2026-11-02，宽松版；2026-11-03 调整间隔）**：总开关下另有「应用锁」，默认关闭；
  开启后冷启动必验证；从后台回来可选「立即」或「10 分钟后」（默认 10），应用锁关闭时该选项整组隐藏；
  旋转/分屏等配置变更不算离开，不会因此误锁。只锁主界面，悬浮球、球面板、文件入口与系统选择器/分享不受影响。
  取消/失败留在锁屏，不提供跳过；也不做“每次使用私钥都要指纹”的强保护。
  日志只写动作与结果，不写生物特征或密钥内容。
- 文件工作流（Phase 4a + 4b 的多文件/目录队列，真实可用）：
  - 通过 SAF 选择任意文件，不申请全盘存储权限；输出只写入应用私有目录 `files/file-tasks/<task-id>/`；
  - **多文件任务队列**：加密/解密页都可一次选择多个文件，按系统返回顺序逐个处理；
    单个文件失败不会中断后面的文件，结果页逐项显示成功/失败原因；每个成功结果可单独分享、
    另存或用其他应用打开；多个成功结果还能「分享全部」（`ACTION_SEND_MULTIPLE`）；
  - **目录递归批量**：也可以用系统文件选择器选一个文件夹，递归收集其中的文件；
    加密模式收所有普通文件，解密模式只收 `.aegix`（跳过其他文件并在提示里显示数量）；
    扫描只读目录信息、不打开文件内容；单批上限 200 个文件 / 4 GB（已知大小）/ 5000 个条目 /

    线格式与桌面端完全一致（两端都走共享 `FileCryptoEngine`）；两端统一 `.aegix`，`.enc` 已不再识别；

    chooser 里排除本应用自身（避免把明文再回灌进解密入口）；加密结果不提供这颗按钮；
  - **接收侧全渠道单入口**：`FileEntryActivity`（透明入口，2026-10-31 从 `MainActivity` 迁入）注册 4 条文件 filter（VIEW 的 `content` scheme-only、
    VIEW 的 `content + */*`、SEND 的 `*/*`、SEND_MULTIPLE 的 `*/*`），**全部不写 intent-filter label**，

    应用被调起后由 `IncomingEntryPolicy` 判型：`.aegix`、密文 MIME、`VOLU` 头或单文件密文结构
    → 解密页，其余 → 加密页；单文件不再弹二选一；
  - **混合批量**：一次分享多个文件且既有密文又有普通文件时，弹
    「只解密 N 个密文 / 只加密 M 个普通文件 / 取消」，只处理选中的子集，另一组本次不导入；

## 3. 悬浮球使用方式

1. 打开应用 → 「设置 → 悬浮球与无障碍」（首页不再保留悬浮球快捷开关）。
2. 「工作模式」是一个开关：
   - **打开 = 便捷模式**：点球就地读写当前输入框，最顺手；开关下方才会出现「无障碍服务」一栏，需在系统设置开启。
   - **关闭 = 标准模式**：完全不使用无障碍，点球打开文字输入面板（自动判断明文加密 / 密文解密），不自动读剪贴板，无障碍栏随开关一起收起。
   - 同一原则贯穿整页：悬浮球关着且已授权时，悬浮窗权限与通知权限都不出现，只留开关与磁贴入口（缺悬浮窗权限时保留「去授权」）；开球后再逐项出现。
   - 首次升级没有模式记录的装机按「系统里无障碍是否已开」一次性迁移，之后只认这个开关。
3. 首次启用会跳转系统「显示在其他应用上层」授权页（应用内已说明用途）。
4. 授权后打开「悬浮球」开关：
   - **单击** → 按当前模式处理文字（便捷模式就地加解密输入框 / 标准模式打开文字输入面板）；
   - **长按** → 展开菜单，只用于选择加密接收方；动作行与工作模式入口已移除；
   - **拖动** → 移动位置，松手后吸附到最近的左右边缘；
   - **点击空白遮罩** → 关闭菜单；
   - 关闭开关 / 撤销权限 → 服务停止、窗口移除。
5. 便捷模式：把光标放进要处理的输入框（微信、浏览器、设置搜索框等都行），单击悬浮球：
   - **合规保护（2026-10-24 新增）**：密码框、PIN 等敏感输入框会被主动跳过（不读也不写，
     设置页「最近一次输入框读写」会显示「密码框已跳过」）；启用无障碍前必须经过披露弹窗，
     勾选**默认不勾选**的同意复选框后才能跳转系统设置，同意时间与文案版本仅存本机。
   - **加密**：读取该输入框的文字，用上次选择的接收方加密并原地替换；要改收件人时长按菜单选择；
   - **解密**：自动解密并校验签名，展示「签名有效 · 来自 X」与明文，并尝试把明文写回同一个输入框；
     写回失败时明文只在胶囊里显示，需要手动复制；胶囊关闭/超时即从内存清除。
   - 输入框为空 / 没有焦点 / 只读 / 发送者不在联系人里，都会给对应提示，且不会改坏输入框；
     文件加解密从首页或系统「用其他应用打开」入口进入（入口内部判型分流）。
   - **已知缺陷（2026-10-28 真机）**：微信聊天输入框的写回没有被回读验证，出现“提示成功但输入框没变”；
     部分选区会因快照比较必然失败。详见 [便捷模式点球交互与微信写回诊断](../docs/android/plans/便捷模式点球交互与微信写回诊断.md)。
6. 标准模式：长按悬浮球，在菜单里选择接收方，然后关闭菜单并单击悬浮球：
   - 在输入框里输入明文 → 点「加密并复制到剪贴板」；
   - 在输入框里粘贴本工具密文 → 自动识别，点「解密」查看明文；
   - 「从剪贴板填入」是可选快捷方式，只有点它才会读剪贴板；
   - 只有一个联系人时会自动选中；多个联系人且未选择时，面板会提示先长按选择并阻止加密。
7. 便捷模式、无障碍服务没连上时（T13，2026-10-29）：**每次**点球都打开专用引导面板。
   - 系统里未启用 → 标题「未开启无障碍服务」，主按钮「去开启无障碍服务」；
   - 系统里已启用但服务没运行 → 标题「无障碍服务没有运行」，主按钮「去修复无障碍服务」，提示关掉再重开一次；
   - 面板里有「便捷模式」开关：关掉后立即切到标准模式，下一次点球打开文字输入面板；
   - 面板打开时**不读剪贴板**；点「先按剪贴板处理」才切到剪贴板区；点「关闭」只关闭，不处理；
   - 面板被系统拒绝后台拉起时 Toast 说明并退回剪贴板兜底，不静默。
   设置页「无障碍服务」行同步显示「未开启 / 服务没有在运行」状态；应用不会替用户打开系统无障碍服务。
8. 首次使用需要先在「密钥管理」创建密钥、在「联系人」添加对方公钥（见第 7 节步骤）。

> 为什么长按还要弹菜单？选接收方需要一个界面；单击则静默就地变形。
> 便捷模式没有可用输入框时才走剪贴板兜底：球窗口会短暂取得焦点来读剪贴板（Android 10+ 限制），
> 读完立刻恢复；不会把主界面拉到前台，也不做滚动、跳转、点按其它控件这类“跨应用自动化”。

> 悬浮球是一个独立的非焦点窗口，**返回键不会关闭菜单**（按键事件不会派发给它）；
> 请点击遮罩或再次点击悬浮球关闭。这是 Android 窗口模型的行为，不是缺陷。

### 控制中心磁贴（Android 7.0+，真实 `TileService`）

应用提供三个快捷设置磁贴，用户在系统的「快捷设置 → 编辑」里自行添加（Android 13+ 支持一键引导）：

| 磁贴 | 类型 | 语义 |
|---|---|---|
| **悬浮球** | 开关（Android 13+ 声明为 `TOGGLEABLE_TILE`） | 开 = 球真的在屏幕上；关 = 服务已停止。状态按「`OverlayService` 是否在运行」判定，所以重启/被强停后显示为关闭，点一下即可恢复 |
| **剪贴板加解密** | 动作型 | 磁贴**不读剪贴板**（服务没有输入焦点，读了也是空），只负责拉起面板；面板拿到焦点后自己读：密文直接解密，明文直接落在加密页 |
| **便捷模式** | 开关型 | 点击在便捷/标准工作模式间切换；未开启无障碍时副标题提醒但磁贴仍可点，不会代替用户打开系统服务 |

- **添加**：设置 → 悬浮球与无障碍 → 「添加到快捷设置」。Android 13+ 调用
  `StatusBarManager.requestAddTileService()` 弹系统添加提示；Android 12 及以下（或厂商未实现该提示）
  会弹手动步骤说明。
- **缺悬浮窗权限时**：磁贴保持可点、副标题显示「需要悬浮窗权限」，点按直接进系统授权页。
  不能把它置为 `STATE_UNAVAILABLE`——实测系统会把这类磁贴设为**不可点**，用户就再也点不进授权页了。
- **长按磁贴**：系统本来固定进「应用信息」；本应用给 `MainActivity` 声明了
  `android.service.quicksettings.action.QS_TILE_PREFERENCES`，三个磁贴长按都会回到应用首页。
  悬浮球磁贴仍控制球，剪贴板磁贴仍拉起面板，便捷模式磁贴切换工作模式。
- **从磁贴拉起界面**：Android 14+ 用 `startActivityAndCollapse(PendingIntent)`，低版本走 Intent 重载；
  全部包在 `runCatching` 里，失败给 Toast 而不是静默。
- **锁屏**：点击统一走 `unlockAndRun`，不会把悬浮球或明文面板叠在锁屏上。
- **零新权限**：`BIND_QUICK_SETTINGS_TILE` 由系统持有，只写在 `<service android:permission>` 上，
  APK 的 `uses-permission` 清单没有任何新增。

## 4. 权限清单（APK 实测）

`aapt2 dump permissions` 结果：

```text
android.permission.SYSTEM_ALERT_WINDOW
android.permission.FOREGROUND_SERVICE
android.permission.FOREGROUND_SERVICE_SPECIAL_USE
android.permission.POST_NOTIFICATIONS
com.cryptoassistant.app.DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION   # AndroidX 自动生成
```

**没有** `INTERNET`、存储、通讯录、相机、位置等权限。
`SYSTEM_ALERT_WINDOW` 由用户单独授权；`POST_NOTIFICATIONS` 仅用于展示悬浮球常驻通知（可选）。
无障碍服务（`TextAccessibilityService`，仅声明系统级的 `BIND_ACCESSIBILITY_SERVICE`）只在你点悬浮球的
那一刻读/写当前焦点输入框；`onAccessibilityEvent` 刻意留空，不监听、不采集、不缓存屏幕内容。
它必须在系统无障碍设置里由用户手动开启，应用无法自行打开。便捷模式无障碍没连上时（含“系统里已启用但
服务没运行”），**每次点球都会打开专用引导面板**（T13/D17，2026-10-29 已实现）：面板不预读剪贴板，内含
便捷模式开关、「去开启/去修复无障碍服务」和「先按剪贴板处理」出口；只有用户明确点剪贴板出口才读取。
设置页「无障碍服务」行显示服务的真实连接状态。标准模式完全不调用无障碍服务。
快捷设置磁贴同样只声明服务的 `BIND_QUICK_SETTINGS_TILE`（系统持有），不会出现在 APK 的权限清单里。

## 6. 已知局限与阻塞（2026-11-06 复核）

1. **中文路径下的 Gradle 单元测试限制**：在 `C:\Users\...\非对称加密工具\android` 中运行
   `testDebugUnitTest` / `:crypto-core:test` 时，Gradle test worker 无法加载测试类
   （`ClassNotFoundException`），与代码无关。2026-11-02 P3 时 `subst` 被系统拒绝，改用
   `%TEMP%` 下的 ASCII 副本并指向真实桌面源码：
   `robocopy android <tmp>\android /E /XD build .gradle .kotlin screenshots docs`，再执行
   `gradlew :app:testDebugUnitTest :crypto-core:test "-Pdesktop.root=<仓库>\src\main\java"`。
2026-11-12 复核：同一提交放到纯 ASCII 路径、用默认 UTF-8 跑，全部通过——限制来自**路径字符集**，
与代码和产品编码无关。项目因此统一 UTF-8，只有路径含中文时才临时给 worker 加 `GBK` 兼容参数（见
   [踩坑 P-01](../docs/agent/pitfalls.md)）。当前基线：app **288/288（46 suites）**、crypto-core **94/94**；
   `lintDebug` **0 errors / 34 warnings**（warning 随文案/依赖漂移）。构建、Lint、安装与设备验证不受影响。
2. **仅用模拟器验收**：Pixel_7 AVD（Android 17）上完成；尚未在真实厂商 ROM 上验证
   悬浮球被系统停止/自启动限制等行为。
3. **输入框读写受应用自身实现限制**：`ACTION_SET_TEXT` 在绝大多数 `EditText`/`WebView` 输入框上可用
   （Chrome、系统设置搜索框已实测），但个别自绘输入框只暴露只读文本或拒绝写入。**微信聊天输入框已在
   2026-10-28 真机确认出现“提示已替换、输入框仍是明文”**：2026-10-30 的阶段 1–3 已改为“恒读整框 +
   写前 `refresh()` 重读 + 150ms→800ms 回读确认”，`writeback=` 只在回读确认后为 true；部分选区
   “选区文字 vs 整框文字”的缺陷同时修掉。**D20（2026-10-29）加的包名/控件结构/选区/WebView 埋点仍在**，
   回读探针已升级为成败判定；微信聊天框读不到是独立问题 H6（T17）。2026-10-30 19:07 的 v1 探针排除了“窗口选错”；19:44 的 v2 探针显示
   root 没有类名、没有子节点。**同日晚上所有者补充“主微信 8.0.79、退回旧版 APK 仍失败、以前能用”，据此把机制定性为 H6-H：
   微信对非白名单的第三方无障碍服务混淆/隐藏节点树**（社区记录见设计 §1.5；注意 2025 年的资料只能证明机制存在，
   **不能用来给这次失效定时**——应用 10-20 开工时微信已是 10-17 更新的 8.0.79，所以那时能读；时点已收口为微信运行期下发（T2），2026-10-31 起暂时搁置，见设计 §1.5）。因此候选回退（P1–P3）作废、探针 v3 降级为可选，
   微信场景改走产品路线（便捷模式“剪贴板即输”、兜底文案；**W1/W3 已于 2026-11-02 随 1.1.0/23 实施**；`ACTION_PROCESS_TEXT` 已于 2026-11-02 目视无系统条目、路线关闭，见设计 §9）。证据与取证步骤见
   [便捷模式点球交互与微信写回诊断](../docs/android/plans/便捷模式点球交互与微信写回诊断.md) §5/§11/§12.11/§12.13。
4. **密钥管理为最小可用集**：不支持重命名、密钥轮换、到期提醒与多密钥；联系人只记录公钥与
   指纹，没有信任状态历史。这些不阻塞悬浮球接入，后续补。
5. **OAEP 参数被显式固定**：桌面 JDK 默认 MGF1-SHA1，Android Conscrypt 默认 MGF1-SHA256；
   `OaepCompat` 显式使用 MGF1-SHA1 以匹配桌面端。若未来更换参数，必须按协议版本升级处理。
6. **2048 位密钥无法生成**：桌面端 `checkRSAKeyStrengthDetail(2048)` 将「建议 4096」当作硬失败，
   Android 复用同一校验，因此生成侧只开放 4096 位；导入/联系人仍接受 ≥2048 位的公钥。
7. **无障碍服务被系统回收后不会自动重连**：服务与主应用同进程，`am force-stop` 或系统回收后
   需要重新开关一次无障碍（或在系统里重新授权）才会重新绑定；未连接时不尝试写输入框。**当前实现**是
   每次点球都打开专用引导面板，面板内可去修复、可关便捷模式、也可先按剪贴板处理一次（T13，见诊断文档 §4）。
   应用不会自行开启无障碍。
8. **悬浮球主题刷新会重建窗口**：切换主题时服务重建悬浮球（位置取最近一次持久化值），
   可能有短暂闪烁。
9. **图标/密码库体积**：Material Icons Extended + BouncyCastle + Gson 使 debug APK 约 25 MB
   （体积随构建/dex 切分变化，不记录固定数字）；后续评估替换为更小的图标方案。
10. **没有全应用首启向导**：无障碍设置仍在「设置 → 悬浮球与无障碍」；便捷模式无障碍没连上时，每次点球都会打开专用引导面板（含便捷模式开关、去开启/修复无障碍、先按剪贴板处理）。用户必须自行在系统设置开启服务，应用不会代为开启。
11. **返回键不关闭菜单**：悬浮窗非焦点窗口，需点击遮罩/球关闭（见第 3 节）。
12. **API 37 未作为 target**：AGP 8.13 支持到 compileSdk 36；升级需要 AGP 9 单独验证。
13. **设备/ROM 覆盖有限**：自动化设备测试以 Pixel_7 AVD 为主；尚未在厂商 ROM 上验证 Conscrypt provider 差异。动画 P0 有单独的所有者真机目测记录，但不等于完整设备兼容矩阵。
14. **两种工作模式仍缺设备专项验收**：标准模式已由历史模拟器记录覆盖空态、输入面板、自动识别、加密/解密、
    菜单接收方（截图 64–67）；设备端 15 条双模式用例未见完整逐项验收记录，待补包括多联系人 UI、
    旋转/进程重建、键盘遮挡、便捷模式 focus-trick 稳定性。2026-10-28 无在线设备，未复测。验收时可按
    《悬浮球权限双模式规划》§9.2 逐条走一遍。
15. **悬浮球面板形变动画**：P-C 真实容器、M-A 同窗口菜单与 P0 窗口策略已实现；所有者 2026-10-27 在真机目测验收打开/关闭无异常。该验收不是 60fps 帧级验证；华为 ROM、完整旋转/IME/返回/TalkBack 矩阵及 Compose UI 中间帧测试仍未做。不要把所有者目测扩大表述成所有设备验收通过。见 `docs/悬浮球形态变换动画评估.md`。
16. **磁贴状态是进程内的**：按 `OverlayService.isRunning` 判定，重启/被强停后显示为关闭，
    点一下磁贴即可恢复；没有做开机自启。
17. **Android 13 以下没有一键添加 API**：只能按弹窗里的手动步骤把磁贴拖进控制中心；
    部分厂商 ROM 也未实现 `requestAddTileService`，会同样回退到说明弹窗。
18. **文件与目录格式边界**：Android 读写当前外部分卷，不生成旧内部多卷容器；多文件/文件夹加密会写出
    **外部分卷**（每个是独立单卷 `.aegix`，自带集合元数据）。VOLU 每卷仍是单文件容器，
    单卷密文长度受 32 位字段限制，但分卷总量不套目录批量 4 GB 上限。
    文件夹分卷只输出 zip、不自动解压和重建目录；解密结果页可选择「解压到文件夹」安全写出。
    签名无效或旧文件缺少 SHA-256 时保留明文但界面警告。
    多文件与目录递归队列的单个目录上限为 200 文件 / 4 GB（已知大小）/ 5000 条目 / 20 层，
    超过明确报错；解密不重建目录结构；批量「分享全部」在只接受单文件的应用里需逐个分享。
    **本轮的 VOLU 验收只覆盖桌面夹具，尚未用真实桌面端生成 201 MB 分卷做手工验收。**
19. **单文件上限 2 GB**：密文长度字段是 32 位有符号整数；加密还要求 SAF 提供准确文件大小，
    系统未给出大小时会阻止加密并提示先保存到本机。
20. **大文件需要额外空间**：输出先写入私有任务目录，加密/解密期间需要约等于结果大小的可用空间；
    120 MB 文件已在模拟器上实测通过。
21. **系统入口已扩为全渠道，但真机候选仍未验证**：`FileEntryActivity` 现在有 4 条文件 filter
    （VIEW 的 `content` scheme-only、VIEW 的 `content + */*`、SEND 的 `*/*`、SEND_MULTIPLE 的 `*/*`），
    全部不写 filter label，选择器统一显示「加密助手」；VIEW/SEND/SEND_MULTIPLE 都走同一后缀判型
    （`.aegix`/文件头密文 → 解密，其余 → 加密），单文件不再弹二选一；混合批量弹子集选择。
    **这只解决「被调起后怎么分流」，不解决「候选列表里没有本应用」**——后者发生在系统把 Intent 交给
    我们之前（Manifest 匹配、包可见性、调用方过滤）。模拟器已用 `query-activities` 与 `am start` 验证，
    微信/QQ/文件管理器的真实候选矩阵**未实测**；完全不带 type 的 SEND 和 `file://` 仍是已知边界。
22. **分享/打开的是临时文件**：结果会保留到「离开页面 / 处理下一个」，但**分享或交给其他应用打开过**的结果
    会按导出租约保留 6 小时再清理——对方可以从「最近文件」重开，代价是明文在私有目录里多留一段时间。
    需要长期保留请用「保存到…」自己选位置。批量结果每个文件有独立任务目录和独立租约。
23. **`.aegix` 对系统不是已知后缀**：本应用按 MIME（含 `application/octet-stream`）与 `*/*`
    filter 匹配，因此也会出现在图片/视频/音频/PDF 等文件的「打开方式」列表里；误点后按后缀/文件头判型：
    能识别为密文就进解密页，否则进加密页；不会静默改写原文件。
    旧 `.enc` 不再识别，新输出统一为 `.aegix`。

## 7. 人工测试步骤（复测清单；不表示本轮已执行）

1. 首页点「本机密钥」→ 密钥页「创建密钥」：输入名称，等待 4096 位生成；确认显示指纹、密钥长度与创建时间。
2. 退出应用再打开，确认指纹不变；点按密钥页身份卡复制公钥，确认剪贴板内容以 `MIIB` 开头。
3. 密钥页「导出密钥备份」：设置 ≥8 位口令并确认，点「导出」后应**直接打开系统保存选择器**，
   保存成功后 Toast「备份已保存」；页面不再出现可复制的备份文本框。
   再点「从文件恢复」→「选择备份文件」选中刚保存的 `.txt`，名称应自动填入、
   提示「完整备份 · 4096 位」，输入口令导入后指纹应一致；
   旧版纯 GCM1 文件也应继续可导入（同样走文件选择，不提供粘贴框）。
4. 联系人页「添加联系人公钥」：粘贴对方公钥，确认显示名称与指纹；重复添加同一公钥应被拒绝；
   添加自己的公钥应提示「这是你自己的公钥」。
5. 不授权悬浮窗，点击「悬浮球」开关 → 跳转系统授权页；返回后保持关闭、状态为未授权。
6. 授权后开启 → 悬浮球出现在屏幕边缘；长按展开菜单（只显示联系人），点击遮罩关闭。
7. 拖动悬浮球到左侧、底部，确认吸边；旋转屏幕/切换主题后仍为圆形且不越界。
8. 在系统设置中撤销「显示在其他应用上层」→ 悬浮球消失，应用显示「已暂停」。
9. 强制停止应用后重新打开 → 悬浮球与密钥均恢复；检查常驻通知与无网络权限描述。
10. 便捷模式：把光标放进输入框 → 点球 → 明文应就地加密、密文应就地解密；要改接收方就长按菜单选择。
11. **标准模式（新）**：在设置里关掉「便捷模式」；先往剪贴板放一段密文，再点球 → 应打开**空白**输入框
    （输入 0 字，证明没有读剪贴板），标题为「文字加密解密」、提示「在里面粘贴明文或者密文进行加密或解密」。
    输入一段明文 → 标题变「加密文字」，只显示接收方与「加密并复制到剪贴板」→
    点击后输入框消失，只留「加密完成 / 加密给 X / 指纹 / 再次复制 / 完成」，并把 `AAACA...`
    密文写入剪贴板（截图 64、67）。
12. 标准模式自动解密：重新点球 → 点「从剪贴板填入」→ 标题变「解密文字」、按钮变「解密」；
    解密后输入框消失，只留「解密完成 / 签名有效 · 来自 测试发送者 / 明文 / 复制明文 / 完成」
    （截图 65/66）。
13. 标准模式接收方：长按菜单只显示联系人单选，没有动作行与工作模式入口；
    只有一个联系人时自动选中；多个联系人且未选择时，输入面板应提示先长按选择并阻止加密。
    单机解密可用种子测试准备一条「加密给本机」的密文：
    ```bash
    adb shell am instrument -w -e class \
      'com.cryptoassistant.app.e2e.BallFlowSeedTest#seedCiphertextForDecrypt' \
      com.cryptoassistant.app.test/androidx.test.runner.AndroidJUnitRunner
    ```
14. 首页「加密文件」→ SAF 选择 `示例文件.bin` → 选择接收方 →「开始加密」；确认两阶段进度、
    结果页显示 `.aegix`，点「分享密文文件」能看到系统 Sharesheet。
15. 点「保存到…」→ 选择下载目录 → 确认提示已保存，并在系统文件中找到该 `.aegix`。
16. 首页「解密文件」应直接停在解密标签；选 `.aegix` 密文 →「开始解密并校验」→
    确认「签名有效 · 来自 桌面发送者」与恢复的文件名一致。
17. 大文件（`big.bin` / `from-desktop-big.aegix`，120 MB）重复加密与解密，期间点「取消」，
    确认立即回到就绪且重新打开应用后没有残留结果。
18. 修改 `.aegix` 任意一个字节后再解密 → 应提示「文件认证失败」，且不显示明文。
19. VOLU 外部分卷读取（自动化已覆盖，手工大文件待做）：`VolumeFileRoutingTest` 在 Pixel_7 上用固定夹具
    覆盖 3 卷、文件夹 zip、篡改与版本 2。手工验收可用 Android 自己打包 >200 MB 的多文件生成多卷 →
    重新导入 → 结果 SHA-256 应与源 ZIP 一致；文件夹分卷应落为 `.zip`，不自动解压，
    但可在结果页点「解压到文件夹」按结构写出。
    **201 MB 真实文件/文件夹分卷的手工验收尚未执行。**
20. 系统「打开方式」接收（无需微信，可先用手造一个 `.aegix`）：
    ```bash
    adb shell am instrument -w -e class \
      'com.cryptoassistant.app.feature.files.IncomingFileRoutingTest#seedDemoEncryptedFileForManualOpen' \
      com.cryptoassistant.app.test/androidx.test.runner.AndroidJUnitRunner
    adb shell am start -a android.intent.action.VIEW \
      -d "content://com.cryptoassistant.app.fileprovider/file_tasks/demo/payload.aegix" \
      -t application/octet-stream com.cryptoassistant.app
    ```
    应直接进入「解密文件」并预填 `payload.aegix`（判型日志应为 `by=head:struct` 或 `by=name:aegix`）；
    点「开始解密并校验」后得到「演示说明.txt」。
    再点「用其他应用打开」：chooser 按 `text/plain` 过滤且不含本应用自身。
21. 用真微信验收全渠道入口：让对方发一个 `.aegix` 文件卡片 → 长按「用其他应用打开」→
    列表里应只有「加密助手」一行；选中后应停在解密页并预填该文件。
    再让对方发一张图片或一个 PDF，同样操作应停在加密页。若文件被改了名、系统也没给 MIME，
    文件头能识别为密文就进解密页，否则按“其余 → 加密”进加密页，不再弹二选一。
    导出日志确认 `file.import.route` 的 `by=`/`conf=`/`nameSource=` 与预期一致
    （**未实测**，模拟器无法登录微信）。
22. 系统分享验收：相册选一张图分享 → 分享面板出现「加密助手」→ 进入加密页并预填；
    文件管理器分享单个文档/未知文件 → PDF/图片进加密页，`.aegix` 应进解密页；
    多选“PDF + `.aegix`” → 弹「只解密 N 个密文 / 只加密 M 个普通文件 / 取消」，选一组只处理该子集；
    纯文本/链接分享若出现本应用，应给「没有包含文件」提示而不是空白页。
    **真实微信/QQ/文件管理器的分享面板仍未实测。**
23. 误点/改名验收：把一张图片「用其他应用打开」→ 应进加密页（非 `.aegix` 默认加密）；
    再把一个改名成 `note.dat` 的密文打开 → 应靠文件头结构识别为密文进解密页；
    把随机二进制 `.bin` 打开 → 按“其余 → 加密”进加密页，不再弹二选一。
24. 目录递归验收：在 `Download/crypto-dir` 下放 `a.txt`、`photo.png` 和 `sub/b.txt`，
    加密页点「选择文件夹（递归）」→ 选中该目录 → 提示读取 3 个文件；开始加密后应得到 3 个
    不重名的 `secure_file_*.aegix`，第三个结果显示原始路径 `sub/b.txt`（截图 61）。
    再准备一个含 3 个 `.aegix` + 1 个 `.txt` 的目录，解密页选它 → 只列出这 3 个密文，
    提示「跳过 1 个非 .aegix 文件」（截图 62）。
25. **D20 微信写回取证（首轮 2026-10-29 04:13；T14 矩阵 6/8 于 10-30 18:24–18:30；T17 v1 于 10-30 19:07、v2 于 19:44，结果见 [诊断 §12.11/§12.12](../docs/android/plans/便捷模式点球交互与微信写回诊断.md)；**2026-10-30 晚按 H6-H 定性后，本步骤降级为可选，不再是微信可用的前提**）**：装本轮 release（`install -r`，不要卸载）→
    设置 → 日志 → 点按等级行切「详细」→「清空日志」；无障碍已连接、便捷模式；在微信聊天输入框分别测
    “无选区 / 部分选区 / 全选”各一次，每次点球后等 1 秒以上再操作；再到 QQ、备忘录各测一次无选区作对照；
    最后长按等级行导出整份日志。导出头应含 `uuid=`/`built=`（证明是新包）与 `ime=`/`a11yEnabled=`；
    正文应出现 `a11y.read`、`a11y.writeback`、`a11y.readback at=150ms/800ms`。
    字段含义与判定方法见 [批次计划 §23](../docs/android/plans/待执行任务批次计划.md) 与
    [诊断文档 §11](../docs/android/plans/便捷模式点球交互与微信写回诊断.md)。v2 探针日志（共 28 行；19:44 起只有微信聊天框）已证明 6 次结果一致，且 root 没有子节点、类名 null；微信侧限制见 [设计 §1.5](../docs/android/archive/微信H6候选回退读取设计.md)。
    下次只需在微信聊天框点一次球，不必重复搜索框/朋友圈；重点是 `probeVer=3` 的敏感标志与 focus 子树。

## 12. 后续工作与当前未完成项（核对于 2026-11-06）

已交付的 Phase 4a/4b 文件工作流、VOLU 外部卷、T1/T2/T3、T11、D15 和批次 E（T9/T12）不再列为待实现功能。下列未做的验收/设计事项应与功能未实现区分：

1. **T6 真机系统入口矩阵（所有者）**：在真实微信、QQ、文件管理器及目标厂商 ROM 上核对候选列表、MIME/文件名、VIEW/SEND/SEND_MULTIPLE 分流和实际分享结果；模拟器验证不能替代。
